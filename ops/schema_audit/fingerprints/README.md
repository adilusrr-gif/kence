# Fingerprint files

Both files here are produced by `ops/schema_audit/fingerprint.py capture`.
Neither is hand-edited.

- **`b0_target.json`** — derived, live. Captured 2026-08-05 by running the
  real `alembic upgrade head` (via the actual CLI, not the Python API
  directly) against a genuinely empty, disposable PostgreSQL 16.13
  container from a clean image (`postgres:16-alpine`), then fingerprinting
  the result. Regenerate this file whenever
  `backend/alembic/versions/bc59de168869_b0_squashed_baseline.py` or
  `backend/alembic/versions/b0_baseline.sql` changes — it must never be
  hand-maintained, so it can never silently drift from what B0 actually
  produces.

  Regeneration command:
  ```
  docker run -d --rm --name b0-target-gen -e POSTGRES_PASSWORD=x -e POSTGRES_DB=t -p 127.0.0.1:0:5432 postgres:16-alpine
  # wait for healthy, then, from backend/:
  DATABASE_URL=postgresql://postgres:x@127.0.0.1:<port>/t python -m alembic upgrade head
  python ops/schema_audit/fingerprint.py capture \
      --database-url postgresql://postgres:x@127.0.0.1:<port>/t \
      --output ops/schema_audit/fingerprints/b0_target.json
  ```

- **`legacy_accepted.json`** — frozen, static. A one-time snapshot of the
  known shape produced by the CURRENT (pre-B0) runtime bootstrap —
  `Base.metadata.create_all()` followed by `_ensure_schema_upgrades()` —
  which is what every real, unmigrated environment (including today's
  actual production database, per Stage A/E.1's evidence) has always
  looked like. This file is committed and does **not** get silently
  regenerated by re-running the capture — it describes a specific
  historical fact (today's accepted legacy shape), not a moving target. If
  the real environment's schema is ever found to have drifted further, this
  file must be re-derived deliberately, from a fresh read-only capture, not
  overwritten mechanically.

  Generated 2026-08-05 against a disposable PostgreSQL 16.13 container
  bootstrapped via the real (unmodified at time of capture)
  `app.core.database.create_tables()` + `app.main._ensure_schema_upgrades()`
  — the same two functions that provisioned every real deployment to date.

Both files exclude `alembic_version` from every category — see
`fingerprint.py`'s module docstring for why (confirmed necessary this
session: including it made the adoption tool's pre-stamp target-verification
step spuriously fail for the unversioned path, since that table does not
exist yet at that point in the transaction).
