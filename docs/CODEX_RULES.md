# KENCE.ai — Codex Rules

# General Rules

- Do not break existing APIs
- Do not modify backend contracts unless explicitly requested
- Do not remove working functionality
- Preserve Docker compatibility
- Preserve existing AI pipelines

---

# Frontend Rules

- Use TailwindCSS
- Use reusable components
- Prefer modular architecture
- Use futuristic glassmorphism design
- Keep responsive layouts
- Avoid monolithic components

---

# Backend Rules

- Preserve FastAPI structure
- Preserve async architecture
- Do not hardcode secrets
- Keep services isolated
- Prefer repository/service architecture

---

# AI Rules

- Preserve RAG compatibility
- Preserve Ollama integration
- Avoid breaking embeddings pipeline
- Keep multimodal scalability in mind

---

# Architecture Rules

- Prefer scalable enterprise architecture
- Keep future PostgreSQL migration compatibility
- Keep future GraphRAG compatibility
- Prefer separation of concerns

---

# Coding Rules

- Avoid massive refactors
- Modify only requested files
- Keep clean imports
- Avoid duplicated logic
- Prefer readability over cleverness

---

# Design Direction

KENCE.ai should feel like:
- enterprise AI operating system
- futuristic intelligence workspace
- neural analytics platform

NOT:
- basic admin panel
- generic CRUD dashboard
- simple chatbot UI
