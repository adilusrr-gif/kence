  # feature_service.py — evaluation logic

  def get_org_features(org_id: int, edition: str) -> dict[str,
  bool]:
      """
      Returns the effective feature set for an org.
      Edition defaults are overridden by per-org DB flags.
      """
      defaults = EDITION_DEFAULTS.get(edition,
  EDITION_DEFAULTS["community"]).copy()

      # Apply org-level overrides from OrganizationFeatureFlags
  table
      with SessionLocal() as db:
          overrides =
  db.query(OrganizationFeatureFlags).filter_by(org_id=org_id).all()
          for override in overrides:
              defaults[override.feature_key] = override.is_enabled

      return defaults


  def require_feature(feature_key: str):
      """FastAPI dependency factory — raises 403 if feature is
  disabled for org."""
      async def _check(
          current_user: dict = Depends(get_current_user),
          org_id: int = None,  # from path param, injected by
  router
      ):
          org = get_org(current_user.get("default_org_id"))
          if not org:
              raise HTTPException(status_code=403, detail="No
  organization context")
          features = get_org_features(org["id"], org["edition"])
          if not features.get(feature_key, False):
              raise HTTPException(
                  status_code=403,
                  detail=f"Feature '{feature_key}' is not available
  in your edition"
              )
          return current_user
      return _check

  Edition Selection Flow

  REQUEST LIFECYCLE WITH EDITION:

  1. User logs in
     POST /api/auth/login
     → returns JWT {sub: "alice"}  (unchanged)

  2. Frontend calls config endpoint
     GET /api/me/config
     → Backend:
         user = get_user("alice")
         org = get_user_primary_org("alice")    ← user's
  default_org_id
         edition = org["edition"]               ← "gov" or
  "enterprise"
         features = get_org_features(org.id, edition)
     → Returns: {username, org, edition, features, ui_labels}

  3. React mounts EditionProvider
     EditionContext.value = {edition: "gov", features: {...}}

  4. App.jsx renders:
     edition === "gov"  → <GovShell />
     edition !== "gov"  → <EnterpriseShell />

  5. Any API call to gated feature:
     GET /orgs/7/graph/query
     → require_feature("knowledge_graph") dependency
     → org.edition = "gov" → feature disabled → HTTP 403
     → Frontend already hid the button, but defense-in-depth

  DESIGN INVARIANTS — MUST NEVER VIOLATE

  1. ONE codebase. Branch = feature, not edition.
     Government Edition is NOT a fork. It is a runtime
  configuration.

  2. NO edition logic in Core services.
     llm.py, document.py, entity_extractor.py have ZERO edition
  checks.
     Edition logic lives only in:
       - feature_service.py (backend enforcement)
       - EditionContext.jsx (frontend rendering)
       - GovShell.jsx / EnterpriseShell.jsx (layout)

  3. Backend always enforces. Frontend always mirrors.
     Hiding a button is UX. The API guard is security.
     Both must be present for every gated feature.

  4. Knowledge Extraction runs on BOTH editions.
     The GOV edition hides the graph visualization.
     It does NOT disable extraction — data is collected and shown
  as "People".
     This ensures GOV deployments build a knowledge base that can
  be surfaced later.

  5. No GOV-specific API routes except /brief and /brief/pdf.
     Everything else uses the same endpoints with feature guards.
     GOV analysts get the same security, same resilience, same AI
  quality.

  6. Edition is an org property, not a user property.
     One user can be a member of a GOV org (sees GovShell) and
     a member of an ENTERPRISE org (sees EnterpriseShell).
     Shell switches on org context switch.
