Вот краткая инструкция для запуска на другой машине:

Перенос: Скопируйте всю папку проекта DocAI (вместе с 

.tar
 файлами, 

.env
 и 

docker-compose.yml
) на новую машину.
Загрузка образов: Откройте терминал в папке проекта и выполните:
powershell
docker load -i docai_backend.tar
docker load -i docai_frontend.tar
docker load -i ollama.tar
Запуск:
powershell
docker-compose up -d
Почему это будет работать «так же»:
Исправление путей: Благодаря тому, что мы заменили жестко прописанный 127.0.0.1 на относительные пути в фронтенде, вам не нужно менять конфиги при переносе. Фронтенд сам поймет актуальный IP адрес машины.
Все зависимости внутри: Все библиотеки (docling, torch и т.д.) уже упакованы в образы. На новой машине не нужно ничего скачивать из интернета.
База данных и настройки: Файл 

.env
 и папка с базой пользователей (

users.json
) переносятся вместе с проектом.
Единственный нюанс: Если на новой машине другой IP-адрес, пользователи будут заходить по нему (например, http://192.168.1.50:3000), и всё сразу заработает благодаря моим правкам в 

api.js
.

Для запуска образов достаточно только 

.tar
 файлов и команды docker load. Однако, чтобы всё заработало так же удобно, как здесь, вам всё равно понадобятся два текстовых файла:


docker-compose.yml
: В этом файле прописано, как именно должны запускаться контейнеры (какие порты открывать, как они связаны между собой и куда сохранять файлы). Без него вам придется писать очень длинные команды docker run вручную.

.env
: Там хранятся настройки (какие модели использовать, ключи и пароли).
Что будет, если перенести только 

.tar
 файлы:
Вы сможете загрузить образы, но контейнеры не будут знать о своих настройках и не будет связи между фронтендом и бэкендом.

Рекомендация (Минимум для переноса):
Вам не обязательно копировать папки node_modules или __pycache__, но лучше всего взять:


.tar
 архивы

docker-compose.yml

.env
Файл backend/app/db/users.json (чтобы не создавать админа заново).
Итог: Лучше просто скопируйте всю папку проекта (без временных файлов), это самый надежный способ. Самое тяжелое там — это архивы, которые вы уже создали.
